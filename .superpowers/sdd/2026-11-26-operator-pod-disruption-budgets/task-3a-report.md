# Task 3A implementation report

## Result

Added typed `podDisruptionBudget` and `scheduling` fields to the shared platform component API. Replica and topology-spread preferences translate into chart values for Traefik, cert-manager, External DNS, External Secrets, Argo CD, and Vault. Chart-native PDB values are used for Traefik, all three cert-manager controllers, all three External Secrets deployments, Argo CD's application controller/server/repo-server, and Vault HA. Argo CD ApplicationSet and notifications use standalone policy/v1 PDBs with separate exact Deployment selectors. External DNS uses a standalone PDB. Vault standalone uses a standalone PDB because the chart's native budget is for HA only.

Vault HA exposes only integer `maxUnavailable`; integer `minAvailable` is translated exactly against replica count. Percentage budgets are rejected for Vault HA because its native value cannot represent them.

`tests/unit/platform-stack.test.ts` received only a mock export for `policy.v1.PodDisruptionBudget`, approved by the task controller, so existing stack tests can exercise the new component path.

## Chart inspection and limits

The codebase leaves platform chart versions unset in `DEFAULT_VERSIONS`; consumers may choose a version, and Helm otherwise resolves the latest. Helm could not access chart repositories in this environment: `helm repo add argocd https://argoproj.github.io/argo-helm` failed with `lookup argoproj.github.io: no such host`. Therefore no chart was rendered locally.

PDB and value paths were checked against upstream chart docs/templates, including the Argo CD chart values, cert-manager chart values, External Secrets chart values, Traefik chart values, and Vault chart schema. Exact rendered selectors could not be verified against a pinned chart release. Standalone PDB selectors are asserted in component resource tests; native PDBs remain generated by the corresponding chart templates.

## Round 1 review fixes

Fixed the Argo CD application-controller native PDB path to `controller.pdb`; the old top-level `values.pdb` path is no longer set. Native budget assertions now cover the controller, server, and repo-server paths. Argo CD component spread constraints are asserted as complete objects per managed workload.

For cert-manager, External DNS, External Secrets, Traefik, Argo CD, and Vault, raw chart replica overrides are preserved when typed `scheduling.replicas` is absent, and the PDB resolver uses the raw desired count with the chart default as fallback. Conflicting typed and raw replica counts are rejected. Typed replicas are written to chart values only when supplied. Vault now rejects `ha: false` with more than one requested replica because its standalone workload cannot scale to match that PDB count.

Tests additionally assert full topology-spread objects per managed workload and exact selectors for standalone PDB resources. Native PDB tests verify chart value paths and the absence of overlapping Nimbus PDB resources. They do **not** verify rendered native selectors: chart versions are unset in the repository defaults and chart repository access failed with DNS `lookup argoproj.github.io: no such host`, so rendering was not possible.
